What a friends-only Magic trading tool needs to feel like a real product

Findings from the current tool, comparable community-built trade matchers, the Scryfall/Cardmarket data layer, and Nielsen Norman Group interaction guidelines. Each recommendation is tied to the prototype in Binder Exchange.

TAKEAWAY 01
Card entry is the bottleneck, not matching.
Every comparable project reports the same friction: typing names, picking the right printing, fixing typos. Autocomplete plus paste-list import removes most of it.
TAKEAWAY 02
A match is not a trade.
The current tool stops at "who has what". Users need a proposal object with value balance, comments, a status, and reserved cards.
TAKEAWAY 03
Cache Scryfall, batch it, and use EUR fields.
Rate limits are strict (2 req/s on named/collection). Prices update once a day. A 24h cache and 75-card batches make hover previews instant.
TAKEAWAY 04
Hover previews need timing, not just images.
NN/g: feedback in 0.1s, reveal after 0.3–0.5s pause, keep 0.5s after leaving, never cover the related row.

1 · Audit of the current tool

Reviewed against Nielsen's ten usability heuristics using the two screenshots supplied (Trades and Binder views). What works: dark, calm palette; one gold accent; a clear "You get / You give" split; roster with collection and wishlist counts. What doesn't:

Visibility of status
"Refresh trades" implies matches go stale. No indication of when data was last computed, whether a friend is active, or whether a trade already started.
→ Live recompute, "last active" per friend, trade status badges on matched cards.
Recognition over recall
Cards are plain text. Traders must remember what "Lotho, Corrupt Shirriff" looks like and is worth. Free-text "Card name" invites typos that silently break matching.
→ Scryfall autocomplete, hover image preview, EUR price on every row.
Error prevention
"Save changes overwrites the current list" and "Clear all" sit one click away with no undo. Two import panels per list duplicate controls.
→ Import preview diff (adds/removes) before commit; undo toast; one import drawer.
Aesthetic & minimalist
Right 40% of the Trades screen is empty; the empty state is a single italic line. Helper copy in the sidebar footer is instructional text nobody reads.
→ Dashboard with best partners and value balance; empty states that suggest the next action.
Contrast
Secondary text (#6b7280-ish on #0f1117) and the monospace "6109 coll · 0 wish" fall under 4.5:1. Gold on dark is fine for headings but the gold outline buttons have low fill contrast.
→ Body text ≥ #b8bcc4 on #0e1015 (≈9:1), muted ≥ #8b919c (≈5.3:1), filled gold buttons with dark ink.
Flexibility
No mobile layout; trading happens at the table, on a phone.
→ Bottom tab bar under 720px; the prototype has a Mobile toggle.

2 · What people who built the same thing learned

Note on sources: Reddit and X threads could not be fetched directly in this session; the evidence below comes from the Deckbox community forum (home of r/mtgtrades), open-source project write-ups and app-store listings of trade tools. Treat it as directional, not a survey.

Matching scales badly if recomputed live for everyone

Deckbox pulled its home-page trade-match widget: a community admin explained it "might work fine in a group with 10-20 people" but the 3,000-member Reddit group caused huge performance issues. Users called it the main reason to visit the site. Deckbox forum, 2013

Your group is ~17 people: compute matches on write (when a binder changes), store them, and show a timestamp. Never on page load.
Inactive traders pollute match lists

Deckbox etiquette guide: many accounts upload a tradelist once and never log in again, and there was no way to hide traders who stopped trading. Deckbox: Online Trading for Dummies

Show "last active" on the roster, sort matches by partner activity, let members pause their binder.
Data entry is where people give up

MTG Bulk Scan was built out of frustration with manually entering cards: "finding the right card, then finding the right set, then finding the right art" until a "literal mountain of cards" piled up. GitHub. MTGdb settled on set + collector number + finish as the unique key and notes non-English cards didn't work. GitHub

Autocomplete on name, default to cheapest printing, optional set picker; store language per row (you asked for it); accept pasted decklists.
Commercial trade tools all converge on "who's ahead, by how much"

Dragon Shield's trade tool compares value between two players and shows who's ahead and by how much, using wishlists and tradelists App Store; ManaBox lets you pick the specific printing to trade App Store; MTG Trades stores past trades with at-the-time prices and tracks loaned cards App Store; Deckbox tracks sent/received cards and trader feedback deckbox.org.

Prototype includes a balance bar, trade history with frozen prices, and reserved cards. Loans and feedback are candidates for later.

3 · Scryfall + Cardmarket integration spec

Autocomplete. GET /cards/autocomplete?q= returns up to 20 English names, nearest match first, ignoring spaces, punctuation and case. Designed for exactly this UI. docs

Batch resolve. POST /cards/collection accepts up to 75 identifiers (name, or set + collector_number) per request and returns a not_found array, which doubles as typo detection on import. docs

Rate limits (hard). search, named, random, collection: 2/s. Everything else: 10/s. A 429 blocks you for 30 s; ignoring it risks a ban. Scryfall asks you to cache for at least 24 h and notes prices only update once a day. Image hosts on *.scryfall.io have no limit. docs Every request needs a real User-Agent and Accept header. docs

Prices in EUR. Use prices.eur and prices.eur_foil; USD and EUR are separate fields since 2019. blog Scryfall's EUR data comes from its Cardmarket partnership announced July 2025. blog purchase_uris.cardmarket deep-links each row to Cardmarket.

Images. image_uris.normal (488×680) for hover, small (146×204) for grid thumbnails, art_crop for avatars. Double-faced cards put images under card_faces[]. docs Fan Content Policy: the data must not be paywalled and end-users must be able to access it with free accounts. docs

// Suggested data flow
1. Binder saved → server collects distinct names
2. Chunk ×75 → POST /cards/collection, 550 ms apart
3. Store id, set, image_uris, prices.eur, color_identity
4. Nightly job refreshes prices (once/day is enough)
5. Client hover = read cache, zero API calls
6. Typeahead → /cards/autocomplete, debounced 250 ms
7. not_found[] → "Did you mean…" on import
Headers: User-Agent: BinderExchange/2.0 (contact) · Accept: application/json

4 · NN/g guidelines applied to hover, motion and contrast

Hover timing

Visual feedback within 0.1 s; wait 0.3–0.5 s of a stopped cursor before exposing hidden content; keep it visible until the cursor has been away for more than 0.5 s. The more disruptive the content, the longer the pause required. NN/g, Timing Guidelines for Exposing Hidden Content

Prototype: row highlight instant, card popup after 350 ms, 120 ms grace on leave, popup anchored beside the name so it never covers the row.
Tooltips

Never put task-critical information only in a tooltip; support keyboard hover too; use arrows when elements are close together; keep tooltips consistent across the site; position so they don't block related content. NN/g, Tooltip Guidelines

Prototype: price and quantity stay in the row; the popup adds image, type and set only. Names are focusable and open the popup on focus.
Motion

Micro-interactions register as responsive in the 100–500 ms window, clustering at the fast end. summary of NN/g animation research

Prototype: screen transitions 350 ms, hover 120 ms, toasts 250 ms, one staggered reveal on the dashboard. A "Reduce motion" tweak turns everything off.
Contrast

Body text ≥ 4.5:1, large headings ≥ 3:1. On #0e1015 the palette used is: primary #e8e6df (15.6:1), secondary #b8bcc4 (9.4:1), muted #8b919c (5.3:1), gold #d4a843 (8.1:1), gold button ink #1a1406 on gold (7.6:1).

5 · Backlog for your friend

NOW · reliability
  • Scryfall autocomplete on every card input
  • Server-side Scryfall cache (id, image, EUR, colours), nightly refresh
  • Hover card preview with NN/g timing
  • Import preview with diff + not_found list, undo after save
  • Store language per binder row
  • Matches computed on save, shown with timestamp
NEXT · trading
  • Trade proposal object: give/get lists, EUR balance, status
  • Comments per trade
  • Reserve cards when both accept; release on decline
  • Trade history with prices frozen at completion
  • Notifications: new match, proposal, comment, accepted
  • Dashboard: best partners ranked by two-way value
LATER · polish
  • Mobile layout (bottom tabs)
  • Printing/set picker, foil flag
  • Pause my binder / last active
  • Loaned cards tracker
  • Multi-way trade cycles (A→B→C)
  • Card grid view with images
